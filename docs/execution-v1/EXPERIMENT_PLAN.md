# 第二章执行方案：复用现有算法迁移到灾后巡查与救援物资运输

日期：2026-10-11。状态：本地源码核查后的实施提案，未实施新场景、未启动训练。本文与旧冻结包分离。

## 1. 本轮决定

第二章研究问题：接收第一章给出的区域和任务初始分配，在局部发生新增物资需求、平台不可用、资源变化或报告延迟时，利用异构平台进行再分配，尽量维持巡查服务和按时物资交付，并控制对原计划的扰动。

采用“现有图策略 + 现有策略优化 + 新场景适配层 + 可单独关闭的动作后果世界模型”。优先复用数学算子、训练逻辑、身份合同和验收方法；场景语义、数据、输入维度和预算重新定义。不开新的算法路线，也不把改名后的旧任务当作运输环境。

第一批交付是可复算的小场景及两个非学习对照；随后接图策略，最后验证世界模型的附加价值。第一章尚无确定输出时，先用明确标记的合成初始分配推进。

## 2. 根据本地最新材料修正进度判断

本轮读取了旧 v7 后续评价恢复目录中的本地报告、结果 JSON、恢复审计和状态文件；三个关键 JSON 的本地 SHA-256 与该报告所列值一致。本轮没有重新远端取证或执行评价，未独立复算全部逐窗统计。

旧 A/B 排序消融已有恢复评价结果：B−A 父场景宏平均 regret 为 +0.000752792，95% 区间 [-0.003627776, +0.007082811]，正值为 B 较差；只有一个 seed 改善。重大损失总计 A 11/189、B 9/189，不能据此抵消平均 regret 未改善。预注册分类为 `no_average_improvement_or_mixed_result`。

因此，旧 v7 原 technical_stop 保留，但“该 A/B 永远未评价”的说法已经过时。新场景默认保留 A 的 pair-weighted 排序定义以减少变更，B 保留为可选研究配置；这不等于证明 A 优于 B。旧模型在该评价中也未优于透明基线，世界模型不能预设为新场景的必然增益。

具体来源和可复用文件见 [SOURCE_REUSE_MAP.md](SOURCE_REUSE_MAP.md)。旧 288 窗口、六个模型及旧评价场景仅作历史分析/回归资料，不直接充当新场景训练或独立测试数据。

## 4. 复用架构与接口

### 4.1 来源选择

1. **图策略优先复用根目录 `src/uav_assignment/paper_faithful_models.py`**：现有 `LiteralUAVAttention`、`LiteralTaskUpdate`、共享 `pair_actor`、NOOP 和 mask 路径。最近世界模型包的池化编码器不替代这套消息传递。
2. **优化器复用 GPPO/PPO 训练骨架**：抽取 rollout、clipped policy loss、value loss、entropy、GAE 与 checkpoint 流程，替换绑定旧环境的构造和奖励接线。PreCo 的通用梯度算法保留，但偏好扩展排在主比较之后。
3. **世界模型复用后果多头和监督逻辑**：masked BCE/Huber、pair-weighted ranking、unknown mask、配对反事实采样方法。预测头语义和输入适配后重新初始化训练。
4. **合同与运行基础设施复用最近修复代码**：结构化 candidate key、PublicPrefix、快照恢复、配置准入、checkpoint 屏障、真实账本、StageServer、systemd 交接和首错保存。

在新开发目录复制经过选择的最小依赖闭包，登记原路径、SHA-256、变更原因与测试。不要运行时跨多个历史冻结目录拼装依赖，不以“目录版本较新”代替接口相容核验。

第一版图保持“平台—任务”两类主节点，区域和货源作为节点/边属性提供，任务前置依赖通过现有关系更新表达。这样保留现有图算子；四类节点的扩展作为后续结构试验，不在首次迁移同时引入。

策略动作先保持“为某平台指定一个可执行任务/订单 + NOOP”；取货、装卸、行进由环境执行阶段推进，不把每个机械步骤扩展成新的学习动作。分配通过一个共同规则更新未承诺队列，所有方法使用相同队列规则；这版结论不宣称解决任意联合路线/序列优化。

公开候选过滤只用已收到的信息。模拟器可在动作执行时发现此前未知的不可行情况，不能用真实隐含需求、未报告故障或库存真值偷偷裁掉候选。内部快照允许含仿真真值用于同状态反事实恢复，但与可送入模型的 PublicPrefix 分开存储和校验。M1加入双状态反例：改变尚未报告的订单/故障、保持已接收信息相同，PublicPrefix、候选、mask及actor输入必须完全相同；隐藏任务的槽位数量也不能泄漏。episode按预定物理期限结束，不能以隐藏订单全部完成来提前终止。

### 4.3 必须改造的尺寸与训练边界

根目录 `src/uav_assignment/paper_faithful_models.py` 有可复用图算子；新场景仍需适配异构特征、实体与候选映射和动态 mask，不能据此声称可变规模已验收。4平台、6任务、25动作只指旧 W1 接线；旧世界模型包也绑定这些尺寸及扁平特征布局。

工程阶段先保留兼容形状验证链路，再引入由样本给出的节点类型、显式active mask、候选ID映射与padding mask。更大规模不得默默截断。L0无消息传递对照也支持同样的输入规模，避免把接口缺陷误当作图泛化优势。

GAE须区分真正终止与时间截断，截断处用正确下一状态bootstrap；事件驱动下每次决策的时间间隔可能不同。首版提案同时按物理时间缩放折扣与trace：`g_t=gamma^(delta_t/time_unit)`、`l_t=lambda^(delta_t/time_unit)`，`delta_t_value=r_t+g_t*b_t*V(s_next)-V(s_t)`，`A_t=delta_t_value+g_t*l_t*c_t*A_next`。其中b在真正终止时为0，时间截断允许bootstrap；c在episode/采样片段边界为0，不能跨reset串联优势。每条transition保存时间间隔、两个mask与bootstrap来源。协议冻结前用手工轨迹复算，并让所有方法一致。

反事实collector的累计回报也从旧 `GAMMA**index` 改为按事件实际时间折扣，后果窗口固定物理时长；窗口内事件奖励和区间成本使用统一时间积分/离散化规则，避免更多决策或更细时间步凭空改变reward。旧公式与训练器不能未经校验整段照搬。

## 5. 世界模型怎么接，怎么判断有用

预测对象是固定后果时间窗内的巡查完成/报告、订单按时交付、未满足需求、能耗、其他任务延误和全局增量。目标订单标签与其他订单外部性分开；unknown继续屏蔽。库存与载荷守恒通过轨迹复算核验。NOOP的目标对象标签可unknown，但全局后果仍应有合法标签。

M0产出训练奖励草案：按已确认交付的订单满足比例增量、已接收巡查报告增量计正奖励，能耗和改派计代价。各分量用固定设计参考量归一化，不用隐藏订单总数作策略可见归一化量；固定偏好权重在M2工程学习前写定。主指标S通过评价真值独立计算，不默认为训练reward。延误等保护指标照常独立报告；是否加入奖励需在正式协议前固定，不按确认结果调权。

R08前固定后果合同：物理窗长H、参考动作（同一C1规则选出的合法动作，必要时NOOP）、窗内累计return定义和公共延续策略。每个分支只强制第一个候选，之后全部使用同一版本C1，分别按各分支当时已接收信息决策，外生事件流保持配对；不能读取未来真值选择续行动作。全局增量为候选与参考分支相同窗长内累计return之差。H和数值权重待工程参数表确定，未确定前不采集正式训练标签。

窗末累计交付量等“截至时刻”标签可以有效；尚未到截止时间的最终按时成功/失败结局标为右删失unknown，不能把未完成填为失败。订单已过截止时间且确定未交付则有明确失败标签。所有标签记录时间窗、有效性、删失原因及参考分支身份。

默认只采用已有 **critic-first** 路径：世界模型冻结后输出作为critic的辅助输入，覆盖rollout value、bootstrap、GAE及更新时的replay；actor不直接用世界模型改选候选，不同时加奖励塑形和特征拼接。策略收益若出现，应解释为训练信号改变后的效果，不能说成实时预测替换了动作。

旧 `ConsequencePolicy.critic_adapter` 输出两目标value、依赖旧base的 `evaluate_encoded()`；根目录图策略返回的是分布与标量value，两者不能直接互换。第一版保留固定偏好下的标量PPO，复用“候选辅助值按策略概率汇总”的运算，适配为标量value增量；向量value与PreCo留到后续偏好阶段。图actor与critic共享部分参数时，critic梯度影响actor表示是方法的一部分，须如实记录。训练后若actor执行确实不依赖世界模型，则部署推理成本按该实际路径计，另报含critic训练/诊断的全成本；不能把无需调用的模型计成必要在线成本，也不能漏掉实际调用。

候选辅助值按动态candidate ID及合法mask对齐，以detach的策略概率加权，不能沿用固定25项reshape。预测器、归一化统计和schema版本在策略学习前冻结；统计只来自训练划分。没有预测支持或只有NOOP时屏蔽辅助通道、保留同容量公共特征路径，记录fallback原因。rollout、bootstrap和replay绑定同一冻结预测身份与特征；有意篡改身份、候选序列、normalization时必须拒绝。

离线预测门首先比较同窗合法候选后果排序、透明动作配对增量、重大负增量及覆盖；通过只是允许测试L2，不能替代最终任务收益。新任务的重大损失阈值与可接受退化按新指标量纲预注册，不沿用旧 `−0.1` 就声称同等风险。

保留失效和延误案例用于学习与评价，不根据新结果挑掉坏样本。旧排序B的负/混合结果不触发无预算的尾部损失、阈值或样本筛选搜索。

## 6. 五个必须完成的实验块

只设两个待验证主张：C1图表示在未见规模/布局上的局部再分配泛化；C2在相同图策略上，动作后果模型提供可重复的额外任务价值且没有不可接受的代价。不是预先保证两项都成立。

| 块 | 系统与划分 | 决定性指标与证据 | 未通过时的解释 |
|---|---|---|---|
| B0 场景正确性 | 人工可解夹具；保留初始计划C0、规则再分配C1 | 手工预期与日志复算一致；报告可见性、货物守恒、局部边界通过 | 工程失败，暂停训练 |
| B1 基础策略有效性 | C0、C1、L0共享实体编码无消息传递、L1图GPPO；同分布独立场景 | L1对强规则C1的任务差异及对L0的表示贡献，代价一起报告 | 保留负结果，定位基础策略，不靠世界模型掩盖 |
| B2 图泛化 | 固定L0/L1 checkpoint；未见数量、布局/分块、能力组合、扰动分别测试 | 父场景配对任务效果、相对同分布退化、模型容量和推理时间 | 仅支持已测分布；任务复杂度不能替代数量泛化证据 |
| B3 模型附加价值 | L2=L1+critic-first；共享训练/确认划分，单独预测门 | L2−L1任务增量、巡查退化、重大损失、额外数据/计算成本，逐seed报告 | 门失败停止L2；在线不改善则不主张世界模型优势 |
| B4 失败与复杂度 | 保存的B1–B3日志，不另外训练新模型 | 最差父场景、外部性、无机会/无解/unknown、完整执行成本 | 确定适用边界，不能事后换主指标 |

L0/L1尽量匹配有效参数量、优化器、环境交互量和更新量，参数差异必须报告。L1/L2固定actor架构、策略训练数据规则及策略更新预算；二者critic均保留相同尺寸的候选辅助适配器与公共候选特征，相同seed配对初始化共享结构，L1屏蔽世界模型特征及其有效位，L2打开冻结预测通道。这样不把新增critic容量误判成世界模型价值；报告总参数与实际激活通道。世界模型增加的反事实环境步、训练、恢复、预测和缓存开销单列，不声称总资源相同。三训练seed为建议起点，具体场景数和精度要求在实测后冻结。

C1规则提案：按已知订单优先级、截止时间排序，选可行最早完成的平台；采用稳定ID消除平局。巡查任务也要进入预定服务规则，不能所有方法任意抛弃巡查。固定初始计划C0只处理必要失效标记，不主动重新分配。两者需公开完整伪代码及失败语义。

偏好控制/PCRL、弱通信协议、额外图节点类型、跨块借机、复杂搜索对照列为后续可选项。当前不把它们并入主实验；若声称事件触发通信优势，再安排真实通信计量和固定频率对照。

## 7. 统一指标和划分

主指标提案：按时物资满足率 `S = sum(w_j * min(q_j_on_time / q_j_required, 1)) / sum(w_j)`。订单需求为正，分子分母的量纲逐订单一致；权重在实验前固定。首版不可拆单，满足比例通常为0或1。分母含截止评价时刻应服务的所有真实订单，包括未发现、无可行承接者和失败订单。无订单场景记N/A。

巡查按时完成率与报告延迟设置预注册保护条件；同时报告物资超时、能耗、重分配次数、既有任务额外延误和完整决策CPU/wall。局部块外受到影响的原任务不能从评估中丢掉。旅行能耗若是简化仿真值，明示假设。

训练、校准、开发、独立确认按父场景隔离，重复、窗口、反事实分支跟随父场景。确认集不用于预测门阈值选择；已经查看的旧场景只能作为开发资料。外生事件tape按物理时间及稳定事件ID定位，随机流分离，使动作数量改变不会改变各方法面对的外部扰动。

父场景内先汇总窗口/重复，再按同一父场景比较各方法；报告各训练seed的差值、seed均值上的父场景配对区间和seed间方向。父场景bootstrap区间不充分覆盖训练seed不确定性，不能把3个seed当成大量独立场景。父场景宏平均与窗口加权同时列出，并清楚区分重大损失事件分母与父场景宏平均率。

成功标准在开发试运行后、查看独立确认结果前冻结：C1要求预指定泛化设置中L1相对L0的优势达到实用差异且区间支持，基线/服务保护条件不退化；C2要求L2相对L1满足任务实用增益、巡查保护、重大损失及成本上限。实用差异、退化限、区间规则和成本数值目前待定，未定完不得开始正式确认。

## 9. 防止重现旧工程停止

- 同一个解析器先构造完整resolved config，并检查任务/场景/parent IDs、阶段名称、恢复模式和资源表；禁止到heldout环境构造时才发现 `scenario` 缺失。
- 同一生产driver在极小工程配置贯通所有阶段；成功路径、无机会路径、失败路径都执行到导出。阶段握手夹具不能替代真实训练及严格恢复。
- 实际发生一次小张量/小模型更新与checkpoint保存、模型/optimizer严格恢复、预测和独立复算；检查所有写入、初始化、加载、forward都预留额度。
- `output_writes`、环境步和各种候选调用依据实际调用表冻结；对拒绝调用和pending保留独立证据，不通过删计量键掩盖实际工作。
- PublicPrefix在flatten前检查，零值合法、unknown拒绝/屏蔽；新增库存、载荷、阶段、报告版本与单位的layout manifest。
- 目标Linux运行时复验最终文件摘要和真实systemd交接；Windows本地通过不能代替。发布排除字节码缓存，训练数据/模型与源码分别登记。
- 阶段训练预算不足时保存可验证的恢复点与完整结算，不能将监督采样超限量当作剩余训练量。停止身份不复用。

## 10. 预算与停止条件

不复用旧21,300秒/13,900秒或1,920次更新作为新场景预算。M4记录每次环境步、候选分支、训练更新、恢复、预测、分析和写盘的耗时/内存/存储；按拟定场景数、训练seed与更新次数推算，给出峰值/长尾余量及停止结算预留。调度、传输与导出单列。

资源表必须包含：训练环境交互、反事实交互、有效窗口、模型更新与forward、checkpoint读写、候选审计、分析次数、文件写入、CPU/wall、RSS与磁盘。共享采集也记账，不能被“缓存复用”掩盖。

工程合同或计量失败：技术停止，保留首错、已有模型、日志和pending。基础策略不改善：先解释B1，暂缓扩大世界模型。预测门失败：L2停止且不改变门。确认结果混合：报告未支持/证据不足，不换指标追求正结论。

本轮仅交付规划、来源清单和任务表；没有模型forward、环境采集、训练、服务器动作或GitHub推送。后续正式实验与短程工程学习需按各自明确的执行范围安排，不视作本规划已执行。
