# 第二章研究计划：灾后巡查与救援运输的局部动态再分配

版本：规划 v1，2026-10-11 修订。本文是实施与实验设计，不是已完成的实验报告。

## 目标与范围

规划一个独立民用多平台应用：灾后巡查，以及药品、饮水等救援物资配送。本文档记录研究与工程准备计划；本次仅归档文档，没有实施新场景或开展正式实验。研究协议须在工程验收及预算评估后、正式评价前冻结。

任务由两类需求组成：对指定点执行巡查（不是逐格覆盖整个地图），以及按取货、装载、运输、卸载和交付步骤完成物资配送。部分配送需求可能要由巡查报告发现。仿真真值可包含尚未发现的需求，规划器只能使用当时可见的巡查报告；训练、验证和报告必须保留这一信息边界。

## 暂定章节结构

1. **全局初始分配**：定义场景、可见信息、任务需求及初始任务归属和顺序，研究如何形成可执行的全局计划。
2. **局部扰动调整**：在计划执行中出现新报告、资源状态变化或任务受阻时，研究局部调整，并记录对既有任务和计划稳定性的影响。
3. **编队执行**：由第三章接收分配结果并研究编队执行，不包含在本次第二章工程范围中。

章节之间的实体与任务数量、任务定义、状态字段及划分方式必须统一。已确认地图为 10x10 格（共 100 格），2x2 局部块是暂定主设定；物理尺寸与坐标单位尚待统一。正式机群与任务数量目前未定，不能把示例参数当成已确认实验设定。

第一章可能也包含动态分配，其与第二章的时间范围、地域范围和决策粒度须书面划分。暂按“第二章处理交接时刻之后的局部扰动”推进；第四章暂未确定。

第二章接收平台区域归属、任务归属、执行顺序和交接状态，输出修订归属、顺序、变更原因及未满足需求。局部块是调整边界，区域外既有任务受到的连带延误仍需计入结果。第三章接收该输出研究编队，不由第二章实现飞行控制。

第一章尚无真实输出时，用标记为 `synthetic_initial_assignment` 的合成接口样例推进，字段要求见 [HANDOFF_REQUIREMENTS.md](HANDOFF_REQUIREMENTS.md)。真实接口到位后替换输入并复验。

## 工程样例提案

建议先用合成、可复现的最小工程样例检查端到端接口：3 架无人机和 1 架直升机。该组合仅为合成提案，未实施，也不是第一章的真实输出或已验证结论。样例应显式区分仿真真值和可见报告，并包含指定点巡查及完整物资交付流程。

第一版只涉及物资，不涉及人员转运或医疗决策。巡查完成需要规定的观察服务与报告，配送完成需要卸载和交付确认；到点不能直接计为配送完成。已装载运输不直接换机，不模拟空中交接；无可行承接者的需求仍进入结果分母。

建议样例包含 2 个巡查点、2 个已知需求和 2 个潜在需求，均标记为合成数据。每类平台的巡查能力、载重、速度、续航和可用状态显式配置；异构性不能只由类型名称体现。

巡查按“分配、到达、观察服务、报告产生、报告接收”记录。配送按“需求可见、分配、取货、装载、运输、卸载、交付确认”记录。记录事件实际发生、被发现和报告到达的不同时间，保持库存、载荷与交付量守恒。

首版分开验证新增需求、平台失效、资源变化和报告延迟，再安排组合扰动。进行中巡查的中断、在途配送的保留和失效平台载荷的结算都要有状态规则。跨块求援若启用，须作为明确动作计费；局部无解则输出未满足需求。

评价可由模拟器真值核算全部需求，但策略不能读取未到达报告。失败、超时、未知和未发现需求均保留；unknown 标签使用 mask，不补成成功或零损失。订单是否可拆分以及中断处理须在工程合同中固定。

## 已有方法迁移清单

| 已有部分 | 可保留思路 | 新场景所需工作 |
|---|---|---|
| GPPO/PreCo、critic、GAE、replay | 策略优化与回放一致性 | 重接状态、合法动作、奖励向量及终止语义 |
| 多头模型、masked BCE/Huber | 已知后果与 unknown 分开 | 重建巡查报告、交付、时限、能耗和其他任务连带后果标签 |
| Candidate key、PublicPrefix、配对快照 | 同一 pre-action 状态的候选比较 | 将库存、载荷、报告版本和任务阶段纳入合同与恢复校验 |
| Pairwise ranking | 同窗候选后果排序 | 保留两种 reduction 定义；历史消融未评价，不能直接认定窗口等权更优 |
| 账本、阶段服务、持久托管 | 额度预留、结算、首错保留 | 新 driver 覆盖全部阶段及实际写入、加载、forward、导出额度 |
| 固定槽位和池化编码 | 旧接口参考 | 建立变长平台/任务接口及关系编码，验收候选索引与 padding mask |

图输入提议包含平台、任务、区域和物资点节点，关系表达能力可行性、任务前置依赖、区域归属和可见旅行代价。图结构、边特征及消息传递属于新工程工作。候选动作先通过能力、库存、载荷、状态和局部边界检查，合法 NOOP 保留。

世界模型以公开 pre-action 状态和候选动作为输入，预测固定后果窗口内的任务结果及外部性。先采用已有 critic-first 接入思路，bootstrap、GAE 和 replay 单独验收；特征拼接和奖励注入不同时引入，以便区分来源。

历史 288 窗口和旧 checkpoint 不自动纳入新场景训练。历史排序 A/B 若需补做评价，应作为独立恢复项目核验六模型和 heldout 输入，不与本场景结果混合。

## 推进阶段

| 阶段 | 工作 | 交付与通过条件 |
|---|---|---|
| P0 场景与接口 | 固定单位、任务语义、异构能力、调整边界和合成初始计划 | 场景合同、schema、状态转换表及待定参数表；完成和无解语义无歧义 |
| P1 最小环境 | 实现巡查发现需求及完整物资配送 | 可复现轨迹与事件日志；守恒、可见性、故障、超时和重复交付拒绝通过 |
| P2 非学习对照 | 保留初始计划、公开规则再分配 | 两种对照、逐任务结果和独立复算；失败及未满足需求不丢失 |
| P3 方法接入 | 图接口、策略/replay、后果标签与 critic 接线 | 受控生产 driver 全阶段收据、checkpoint 屏障、正常/失败导出及耗时/存储样本 |
| P4 实验冻结 | 固定划分、对照、指标、种子、预算和停止标准 | 协议、冻结清单、实测预算、唯一入口及目标服务器运行时验收 |
| P5 正式实验 | 先验证图策略，再验证世界模型附加价值 | 配对结果、模型制品、失败案例和资源结算，严格遵守冻结规则 |

后续工程阶段的交付目标是场景可运行、两种对照及受控验收完成。当前归档不代表这些工作已经实施，也不包含正式训练批准。

当前优先推进 P0-P2。未知参数可使用显式标记的工程值推进，但正式实验前必须统一。生产验收使用最终源码和真实 driver、BudgetLedger、StageServer 及托管入口；合成 runner 的阶段通过不能代替真实张量训练或严格 checkpoint 恢复。

## 对照矩阵与研究假设

| 编号 | 方案 | 比较目的 |
|---|---|---|
| C0 | 保留初始计划；失效任务记为未满足，不添加主动再分配 | 衡量动态调整的必要性 |
| C1 | 能力与库存约束下的公开规则再分配 | 可解释、可复算的非学习对照 |
| L0 | 非图策略，无世界模型 | 图表示消融，保持观察信息和优化器一致 |
| L1 | 图策略，无世界模型 | 验证图表示及未见场景表现 |
| L2 | 与 L1 同一图策略，加动作后果世界模型 | 验证世界模型附加价值及在线成本 |

C1 暂建议按可见优先级、截止时间及可行完成时间排序，确定性消除平局，正式协议前写出算法。Hungarian 若作为附加对照，其约束与任务含义须一致。

L0/L1 尽量匹配模型容量、环境交互、更新次数和优化设置，报告参数量。L1/L2 使用共同场景、扰动和初始计划；世界模型额外数据、反事实采样、训练和推理成本单列。额外资源条件下的收益不能声称来自相同总预算。

L0 也须支持相同变长输入，例如共享逐实体编码与池化，但不进行关系消息传递。不能用无法接收更多实体的固定槽位网络作为唯一对照，从而把接口限制当作图模型泛化优势。

图泛化假设比较未见规模或布局上的性能变化与 L0 的差异。世界模型假设比较 L2 相对 L1 的配对任务增量、重大损失和成本。事件触发先作为共同规则；若主张减少通信或触发成本，需要固定频率对照并真实计量。报告延迟条件不等同于已实现弱通信协议。

偏好控制作为主比较后的扩展。主比较先固定偏好，再测试未见偏好；若实现 PCRL 对照，统一目标归一化和 HV 参考点，不能借用论文数值作为本场景结果。

## 指标、数据划分与统计口径

| 类别 | 指标 | 计算要求 |
|---|---|---|
| 主任务效果 | 提议采用优先级加权订单按时满足率 | 按订单需求比例归一化，权重预注册；巡查完成单独报告 |
| 服务结果 | 巡查完成率、报告延迟、配送满足率、超时率、未满足需求 | 包含潜在及无可行承接者需求，注明评价截止时刻 |
| 调整代价 | 归属变更、顺序变化、额外旅行和既有任务延误 | 明确分母及初始计划基准，计入区域外连带影响 |
| 资源效率 | 能耗、交付耗时、平台利用率 | 公开仿真单位与假设；未校准模型不声称实际飞行性能 |
| 泛化 | 未见规模、布局、组合及扰动的性能与相对下降 | 固定 checkpoint 测试，不在测试集追加训练 |
| 世界模型诊断 | 有效标签误差、候选 regret、机会覆盖、重大负增量 | 宏平均和窗口加权均报告；阈值预注册 |
| 在线成本 | 完整决策 CPU/wall 分布、RSS、触发次数 | 包含编码、过滤、预测及动作选择，披露计量缺口 |

主指标、可接受退化、重大损失定义和成本上限在查看正式结果前冻结。辅助指标改善不能自动抵消主任务退化，也不能实验后挑选有利指标证明优势。

主指标建议公式为 `sum(w_j * min(delivered_on_time_j / required_j, 1)) / sum(w_j)`，其中 `required_j > 0`，交付量与需求量使用该订单相同单位，`w_j` 为预先规定的优先级权重。这样不同物资不直接按公斤、升或件数相加。分母包括评价场景全部订单（含未发现和不可承接），逾期交付不计入按时量；无订单场景记为不适用，不补为满分。巡查按时完成率与报告延迟另设预注册退化限制，避免通过放弃巡查提高配送指标。该公式仍是待冻结方案。

按父场景划分训练、校准、开发和独立确认集。实例的重复和反事实分支跟随同一父场景，不跨集合。用于错误分析的确认场景之后转为开发材料，后续确认使用未查看场景。

泛化按平台/任务数量、地图布局/局部划分、异构能力组合、扰动强度/报告延迟四条轴分别研究，先单轴再组合。增加任务复杂度不能代替跨平台数量泛化证据。正式场景数、种子与重复数依据实测资源和估计精度确定，当前不写成已批准配额。

每个父场景使用相同初始计划、扰动和种子完成方案配对。以父场景为统计单位报告配对差与置信区间，多窗口不视作独立场景。列出各训练 seed、最差父场景、最差两场景和重大损失案例，区别主比较与探索比较。

Regret 仅针对保存的合法候选和规定后果窗口，不等同于全局最优差距。NOOP、无机会和 unknown 数量单列，不通过过滤提升表现。

## 停止规则与结果解释

- 合同、恢复、可见性、守恒或账本失败，结算为技术停止，保留首错和 pending，不自动重试。
- 世界模型先通过冻结的独立预测门；失败则停止其在线分支，预测改善不能替代任务收益。
- 在线运行达到冻结的资源、重大损失或成本停止条件，保存部分结果并停止，不临时放宽。
- 正常完成后依据预注册比较说明支持、未支持或证据不足；未训练、未评价和技术停止分别标记。
- 历史 v7 排序 A/B 的效果仍未评价，接口故障不构成算法有效或无效的证据。

## 比较与证据

正式研究前应先固定统一场景接口和任务完成规则，通过工程验收，再建立非学习对照与评估划分。预算和可用资源评估后才能提出正式运行申请；本计划不指定确定的运行配额或时长。

证据至少应支持以下相互独立的问题：

- **泛化**：在预先定义且隔离的场景划分上评估，报告跨地图、任务组合及扰动条件的表现与不确定性。
- **偏好一致性**：预先说明偏好输入及对应的评价规则，检查输出是否依照偏好改变，并报告冲突和退化情形。
- **世界模型决策价值**：与明确的无模型或非学习对照比较，隔离模型带来的决策影响，并报告预测误差及其对任务结果的关系。
- **多目标质量**：若比较 PCRL，应按预注册协议报告其 HV、CS 等适用指标；不能以增加若干其他指标取代这些指标，也不能仅凭单一聚合分数宣称优势。

所有指标、基线、随机种子、划分、统计方法和停止规则应在实验前确定。结果应覆盖收益与重大损失等不同后果，披露失败案例和不确定性。未经这些证据，不得声称方法优越或可靠增益。
