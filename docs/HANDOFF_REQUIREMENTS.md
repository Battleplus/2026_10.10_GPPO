# 交接要求

在启动跨章节工作前，负责方应提交统一接口表，并标明每项是已知、待定还是仅为合成示例。待定字段必须保留待定标记；不得由样例默认值伪装成第一章真实输出。

| 接口字段 | 当前状态 | 交接要求 |
|---|---|---|
| 地图范围、单位、坐标原点与格/块含义 | 已确认 10x10 共100格；2x2块暂定；物理尺寸和单位待定 | 明确指定点如何落在地图上及单位换算；未建模障碍时不得声称已验证避障 |
| 实体 ID、类型与初始状态 | 待定；3 无人机 + 1 直升机仅为合成提案 | 定义稳定 ID、位置、载荷、状态及各章共享字段 |
| 实体能力与限制 | 待定 | 描述巡查、载运、续航和并发限制及其来源；不得臆定能力参数 |
| 任务 ID、位置、需求量、优先级与前置关系 | 待定 | 区分指定点巡查与物资需求；明确单位、可分割性及时间属性 |
| 需求可见性与报告 | 待定 | 分开保存模拟器真值、已发现事实和决策者当时可见报告；记录发现时间与信息来源 |
| 初始归属与任务顺序 | 待定 | 给出第一章输出 schema、可行性校验及失败表达；合成工程样例不得冒充真实输出 |
| 取货、装载、运输、卸载、交付 | 待定 | 为每个阶段定义前置状态、载荷变化、位置条件、失败和重复调用语义 |
| 章节交接快照 | 交接时刻待定 | 第一章提供飞机位置、剩余资源、初始归属和任务进度，统一版本与时间戳；此处不指货物跨机交接 |
| 扰动与局部调整 | 待定 | 明确可触发调整的事件、允许改动范围以及对已承诺任务的处理规则 |
| 完成、失败与取消规则 | 待定 | 分别定义巡查完成、需求交付完成、部分完成、超时和不可行状态 |
| 数据划分与随机性 | 待定 | 固定地图、任务组合、扰动、种子及防泄漏边界；真值和可见信息均纳入追踪 |

建议交接材料包括接口表、少量人工可读合成样例、字段校验规则、状态转换示意和待决问题清单。交付前检查章节一至三对字段名、单位、ID、完成规则和可见性假设的一致性。

## 阶段门槛

1. 场景定义和接口字段经审核，且真值与报告可见性边界明确。
2. 非学习基线、任务完成规则、评估划分和证据指标书面确定。
3. 工程样例通过接口和流程验收，失败路径可解释。
4. 评估实现工作量、计算资源和预算，再单独提交正式研究运行申请。

这些门槛用于规划交接，不代表正式研究或运行已获授权；不预设确定的运行配额或时长。
